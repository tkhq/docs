## Control autonomous agents

Agent adoption often stalls at the last mile: the agent can research and propose, but the business cannot safely let it approve a payment, change production state, or release data. [Agent control](/solutions/verifiable-cloud/agent-control) puts the narrow, high-risk decision path in code that counterparties can identify and verify.

## Verify sensitive data processing

Analytics often settle disputes between parties who do not share infrastructure or incentives. [Verifiable analytics](/solutions/verifiable-cloud/verifiable-analytics) lets an application sign a result with an enclave-specific key so a verifier can connect that result to the approved code and configuration that produced it.

## Broker credentials and capabilities

The usual workaround for machine access is to distribute a long-lived credential or hand raw data to an intermediary. [Sensitive data brokerage](/solutions/verifiable-cloud/sensitive-data-brokerage) combines policy-gated secret release with a verifiable processing boundary, so access can be limited to a defined application workflow.

## The shared trust model

These solutions use the same two keys for different jobs:

- The **Quorum Key** is the TVC application's long-lived key. It can encrypt or sign state that must remain usable across approved software upgrades. Its persistence is governed separately from code provenance.
- The **Ephemeral Key** is generated inside one enclave at boot. An [App Proof](/features/verifiable-cloud/proofs-and-verification#app-proof) signed by this key links an application statement to the [Boot Proof](/features/verifiable-cloud/proofs-and-verification#boot-proof) for that enclave and, through the manifest, to the exact code and configuration that ran.

An App Proof establishes who signed a defined statement and which approved code held the signing key. Its value depends on the application's proof schema and verifier. It does not, by itself, prove that inputs were truthful or complete, hide public-ingress traffic, or make every claim about an application's behavior true.

## Start with the decision

TVC is most useful when all three are true:

1. A decision or output has material consequences.
2. The parties cannot rely on the application operator's logs alone.
3. A narrow program and proof payload can capture what those parties need to verify.

If the real requirement is general-purpose compute with no independent verifier or governed key boundary, conventional cloud infrastructure is usually the simpler choice.
