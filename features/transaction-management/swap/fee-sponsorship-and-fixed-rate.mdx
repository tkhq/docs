Two optional features change who pays for a swap:

- **Fee sponsorship:** your organization pays the swap provider's fees (execution, swap, and platform fees), so the wallet keeps more of the output. Your own client fee is not sponsored. Sponsored fees are billed to your organization.
- **Fixed rate:** for a pair of supported stablecoins, the wallet receives the quoted output at a fixed rate instead of the market rate at settlement. When the market rate is below the fixed rate, your organization is billed the difference. When it is above, the difference is credited against your transaction management charges at the end of the billing period.

Each feature is turned on, and capped, by a **spending window**: a USD limit over a rolling period that the parent organization sets. Quotes then request the features they want.

**Prerequisites:**

- Your parent organization is enabled for early access, and is on Pay As You Go, Pro, or Enterprise.
- Only the parent organization can change spending windows. Sub-organizations use their parent's features and limits.

## Turn a feature on

Submit one activity per feature from the parent organization:

| Feature | Activity | Route |
| :-- | :-- | :-- |
| Fee sponsorship | `ACTIVITY_TYPE_UPSERT_SWAP_FEE_SPONSORSHIP_LIMIT_CONFIG` | `/public/v1/submit/upsert_swap_fee_sponsorship_limit_config` |
| Fixed rate | `ACTIVITY_TYPE_UPSERT_SWAP_FIXED_RATE_LIMIT_CONFIG` | `/public/v1/submit/upsert_swap_fixed_rate_limit_config` |

Both take the same parameters:

<ParamField body="parameters.orgWindowLimitUsd" type="string" required>
  The USD limit for the window, shared by the parent organization and all of its sub-organizations, e.g. `"1000"`. Up to 18 integer and 12 fractional digits.
</ParamField>

<ParamField body="parameters.subOrgWindowLimitUsd" type="string" required>
  The USD limit for each sub-organization, no greater than `orgWindowLimitUsd`.
</ParamField>

<ParamField body="parameters.windowDurationMinutes" type="string" required>
  The rolling window length in minutes, e.g. `"1440"` for one day.
</ParamField>

<ParamField body="parameters.enabled" type="boolean" required>
  `true` turns the feature on. `false` turns it off and keeps the saved limits.
</ParamField>

Turning a feature on or off changes your organization's signed configuration, so it needs root quorum approval, like any other organization feature change. Changing the limits of a feature that is already on follows your policies.

```bash title="cURL"
curl --request POST \
  --url https://api.turnkey.com/public/v1/submit/upsert_swap_fee_sponsorship_limit_config \
  --header 'Accept: application/json' \
  --header 'Content-Type: application/json' \
  --header "X-Stamp: <string> (see Stamps)" \
  --data '{
    "type": "ACTIVITY_TYPE_UPSERT_SWAP_FEE_SPONSORSHIP_LIMIT_CONFIG",
    "timestampMs": "<string> (e.g. 1745474677453)",
    "organizationId": "<PARENT_ORGANIZATION_ID>",
    "parameters": {
      "orgWindowLimitUsd": "1000",
      "subOrgWindowLimitUsd": "100",
      "windowDurationMinutes": "1440",
      "enabled": true
    }
  }'
```

With the Go SDK, use `Client.UpsertSwapFeeSponsorshipLimitConfig` and `Client.UpsertSwapFixedRateLimitConfig`.

## Request a quote

Request the features per quote with `ACTIVITY_TYPE_CREATE_SWAP_QUOTE_V3`. It uses the same route and parameters as [`ACTIVITY_TYPE_CREATE_SWAP_QUOTE_V2`](/features/transaction-management/swap/get-swap-quote), plus two flags:

<ParamField body="parameters.feeSponsorship" type="boolean">
  Optional, defaults to `false`. When `true`, your organization pays the provider's fees for this swap.
</ParamField>

<ParamField body="parameters.fixedRate" type="boolean">
  Optional, defaults to `false`. When `true`, the wallet receives the quoted output at a fixed rate. Both `inputToken` and `outputToken` must be stablecoins supported for fixed rate. Same-chain and cross-chain routes both work.
</ParamField>

The flags are independent; set either or both.

```bash title="cURL"
curl --request POST \
  --url https://api.turnkey.com/public/v1/submit/create_swap_quote \
  --header 'Accept: application/json' \
  --header 'Content-Type: application/json' \
  --header "X-Stamp: <string> (see Stamps)" \
  --data '{
    "type": "ACTIVITY_TYPE_CREATE_SWAP_QUOTE_V3",
    "timestampMs": "<string> (e.g. 1745474677453)",
    "organizationId": "<ORGANIZATION_ID>",
    "parameters": {
      "signWith": "<WALLET_ACCOUNT_ADDRESS>",
      "inputToken": "eip155:8453/erc20:0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
      "outputToken": "eip155:42161/erc20:0xaf88d065e77c8cC2239327C5EDb3A432268e5831",
      "inputAmount": "1000000",
      "feeSponsorship": true,
      "fixedRate": true
    }
  }'
```

With the Go SDK, use `Client.CreateSwapQuoteV3`. The TypeScript SDK's `createSwapQuote` sends V2; until it adds V3, submit the activity with a stamped request as above.

The result is in `activity.result.createSwapQuoteResultV2.quotes`. Each quote has the V2 fields plus:

- `feeSponsorship`, `fixedRate`: the features this quote applies.
- `estimatedFixedRateAdjustmentUsd`: fixed-rate quotes only. The estimated USD cost of the fixed rate: positive is billed to you, negative is an earning credited against your transaction management charges at the end of the billing period. It is informational; the final amount is settled after the swap completes.

With fee sponsorship, `outputAmount` and `minOutputAmount` are no longer reduced by the provider's fees. Your client fee, if configured, still applies and is reflected in both.

## Execute the quote

Submit `ACTIVITY_TYPE_EXECUTE_SWAP_V3` with the quote's `quoteId`, amounts, and `minOutputAmount`, exactly as for a V2 quote. The quote binds the features, so nothing else changes. See [Execute a Swap](/features/transaction-management/swap/execute-swap).

Fee sponsorship and gas sponsorship are separate. Fee sponsorship covers the provider's fees and is set on the quote. Gas sponsorship covers the origin-chain transaction's gas and is set with `sponsor: true` on execute.

## Check usage

`POST /public/v1/query/get_swap_sponsorship_usage` returns each feature's state and what is left in its window.

```bash title="cURL"
curl --request POST \
  --url https://api.turnkey.com/public/v1/query/get_swap_sponsorship_usage \
  --header 'Content-Type: application/json' \
  --header "X-Stamp: <string> (see Stamps)" \
  --data '{ "organizationId": "<ORGANIZATION_ID>" }'
```

```json title="Response"
{
  "feeSponsorship": {
    "permitted": true,
    "window": {
      "enabled": true,
      "windowDurationMinutes": 1440,
      "windowLimitUsd": "1000",
      "subOrgWindowLimitUsd": "100",
      "usageUsd": "12.48",
      "remainingUsd": "987.52"
    }
  },
  "fixedRate": {
    "permitted": true,
    "window": {
      "enabled": true,
      "windowDurationMinutes": 1440,
      "windowLimitUsd": "500",
      "subOrgWindowLimitUsd": "50",
      "usageUsd": "0",
      "remainingUsd": "500"
    }
  }
}
```

- `permitted`: the feature is on for the parent organization. Quotes can use it only when it is permitted and its window is enabled.
- `window`: absent until the parent saves a spending window.
- `windowLimitUsd`: the parent limit, or the per-sub-organization limit when a sub-organization queries.
- `subOrgWindowLimitUsd`: returned only when the parent queries.
- `usageUsd`: settled spending in the current window. A swap counts once its final cost is recorded, shortly after it completes. Fixed-rate usage nets earnings against costs and never goes below zero.
- `remainingUsd`: limit minus usage, floored at zero. For a sub-organization, also capped by what the parent has left.

## Errors

A quote that can't apply a requested feature fails rather than falling back to an unsponsored or market-rate quote:

| Error code | Meaning |
| :-- | :-- |
| `SWAP_FEATURE_NOT_ENABLED` | The parent organization hasn't turned this feature on. |
| `SWAP_FIXED_RATE_PAIR_NOT_ELIGIBLE` | The token pair isn't eligible for a fixed rate. |
| `SWAP_FIXED_RATE_UNAVAILABLE` | The provider can't offer a fixed rate for this swap right now. |
| `SWAP_FEE_SPONSORSHIP_UNAVAILABLE` | The provider can't sponsor fees for this swap right now. |

A quote is also rejected when the feature's spending window is disabled, or when the swap's estimated cost would exceed the window's remaining capacity. [Check usage](#check-usage) or raise the limit.
